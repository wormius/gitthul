# GitThul 1.2.0

GitThul™ 1.2.0 permite identificar repositorios con un alias, copiar texto desde
los diffs y Resolver, copiar SHA desde los detalles y aplicar solo los archivos
que necesitas de un stash.

Los paquetes de esta versión están en [GitHub Releases](https://github.com/wormius/gitthul/releases/tag/v1.2.0).

## Alias de repositorios

**Asignar alias…** está disponible en el menú contextual de los repositorios y
de sus pestañas abiertas. El alias aparece en las listas, espacios, pestañas,
búsqueda y cabecera de GitWorking, y se conserva al volver a abrir la aplicación.
Vaciar el campo restaura el nombre original. La carpeta y la identidad Git del
repositorio se mantienen.

Un doble clic sobre el nombre de una pestaña permite editar el alias directamente.
Enter o un clic fuera guarda; Escape cancela. El cambio se refleja en todas las
pestañas del mismo repositorio, incluidas sus terminales.

## Más avatares y dibujos renovados

Los 85 avatares anteriores se redibujaron con siluetas más definidas y detalles
que se distinguen mejor en las filas y pestañas. El catálogo compartido de
repositorios y perfiles crece a **128 dibujos**, con 43 opciones nuevas,
incluidos 20 símbolos: código, control de juego, planeta, OVNI, poción y más.
También llegan animales como el ajolote y el capibara, plantas, festividades y
figuras abstractas. Se conservan las cinco categorías, los colores y las
selecciones guardadas.

## Copiar desde los diffs, Resolver y los detalles

- El menú contextual del diff ofrece **Copiar selección** y **Seleccionar todo**
  en commits, WIP y stashes. También funcionan **Ctrl+C** y **Ctrl+A**, o **Cmd**
  en macOS. En la vista dividida, la selección completa abarca el lado enfocado,
  incluidos todos sus hunks.
- Todos los editores de Resolver ofrecen las mismas acciones: A, B, resultado
  editable y vistas de resultado resuelto y revisión. Seleccionar o copiar
  conserva las decisiones del conflicto; cada panel selecciona su propio texto.
- Los números de línea y las marcas visuales de espacios y tabuladores quedan
  fuera de la copia. Se conservan los caracteres y finales de línea del texto
  que recibe el visor.
- El botón junto al SHA de un commit o stash copia su identificador completo.
  Los fallos de acceso al portapapeles se muestran en un aviso.

## Aplicar parte de un stash

Selecciona uno o varios archivos en los detalles del stash y abre su menú
contextual para aplicarlos. La vista de árbol también permite aplicar los
archivos de una carpeta.

Los cambios quedan en el árbol de trabajo. El Stage conserva su contenido y
el stash permanece disponible para aplicar otros archivos después. La acción
admite Deshacer/Rehacer, archivos binarios, nuevos, eliminados, sin seguimiento
y renombrados; estos últimos incluyen la ruta anterior y la nueva.

Los archivos elegidos deben estar libres de cambios locales; puedes conservar
cambios en otros archivos. Una colisión o un parche incompatible rechaza la
selección completa. Los cambios de submódulos requieren aplicar el stash
completo. La aplicación parcial no inicia una resolución de conflictos ni
elimina el stash.

## Elegir dónde aparecen las notificaciones

En **Configuraciones → Apariencia**, la posición se elige sobre un esquema de
la ventana. Selecciona una de sus cuatro esquinas para ver una notificación de
prueba en esa ubicación. La esquina activa queda marcada; también puedes
cambiarla con las flechas del teclado y restablecer la posición predeterminada.

## Administrar el espacio de respaldos

En **Configuraciones → Respaldos y caché** puedes eliminar respaldos anteriores
de forma individual, después de revisar su repositorio y fecha. El respaldo
válido más reciente de cada repositorio permanece protegido. El borrado verifica
los datos conservados y solo libera los bloques que ninguna otra copia necesita;
el repositorio original se mantiene.

**Depurar respaldos…** permite retirar todos los puntos no protegidos en una
sola operación, con confirmación. Una barra de carga indica la primera consulta,
las actualizaciones solicitadas y la depuración. Las consultas automáticas
posteriores son silenciosas y mantienen disponibles la eliminación y depuración;
las acciones manuales tienen prioridad segura frente a la cola de respaldos.

Una barra muestra el espacio ocupado y su porcentaje respecto al límite global
configurado para respaldos. Se actualiza al eliminar una copia y refleja los
datos compartidos sin contarlos varias veces.

Cuando falta espacio para preparar un respaldo, GitThul libera las versiones
adicionales necesarias entre todos los repositorios y conserva la última copia válida
de cada uno. Al reducir el límite, muestra el impacto y pide confirmación si
debe eliminar versiones. Un límite que no permite conservar las copias protegidas
se rechaza con una indicación del mínimo necesario.

## Validación y compatibilidad

Las pruebas automatizadas comprueban persistencia y edición directa de alias,
menús y selección, portapapeles y aplicación parcial con repositorios Git
descartables. Las pruebas de respaldos cubren corrupción, datos compartidos,
operaciones simultáneas, consultas automáticas sin bloquear los controles y
prioridad segura de la depuración durante una captura. La verificación de
frontend también incluye selección continua entre hunks y conservación de sus
controles de Stage. La administración del límite comprueba el impacto antes de
depurar, conserva las copias protegidas y exige revisar otra vez un plan que haya
cambiado. Los fallos de persistencia y la falta de espacio temporal también se
cubren con pruebas.
Las comprobaciones de avatares cubren los 128 dibujos, la conservación de todos
los identificadores anteriores, traducciones y selección guardada en repositorios
y perfiles. El selector se revisó en ambos temas y en una ventana de 320 px.

La revisión visual en navegador utiliza datos simulados y cubre los temas claro
y oscuro. En Linux x64 finalizaron correctamente las comprobaciones de tipos,
lint y formato, la compilación web y la compilación nativa actual, sin
instaladores. Lint conserva dos advertencias de TanStack Virtual y Vite avisa
del tamaño del chunk principal.

La interfaz nativa y la instalación de paquetes de esta versión todavía no se
han comprobado manualmente en Linux, Windows o macOS. Los instaladores de Windows
no tienen certificado comercial; las aplicaciones de macOS usan firma ad hoc y
no están notarizadas. El código propio se distribuye bajo MIT.

## English summary

GitThul™ 1.2.0 adds persistent repository aliases throughout repository lists,
spaces, tabs, search and GitWorking. Double-click a repository tab name to edit
its alias in place; Enter or a click outside saves, and Escape cancels. Repository
paths and Git identities stay unchanged. Diff and Resolver editor context menus
support copying selected text and selecting the entire focused panel, with
Ctrl/Cmd+C and Ctrl/Cmd+A. This
includes both conflict sides, the editable result and result review panels,
without changing conflict decisions. Commit and stash details include a button
to copy the full SHA.

All 85 existing avatars have been redrawn with bolder silhouettes and clearer
detail. The shared repository and profile catalog now contains 128 drawings,
including 43 additions and 20 new symbols. Existing selections and colors are
preserved across the five categories.

Apply selected stash files from their context menu while preserving the stash
and the current index. Unrelated local changes can remain; selected files must
have no local changes. Conflicting patches, destination collisions and submodule
changes are rejected. Partial application supports undo and redo.

Appearance settings now include a window diagram for choosing the notification
corner, with a marked selection, keyboard navigation and a live sample.

Older backups can be deleted individually after confirmation. The most recent
valid backup of each repository remains protected, retained data is verified,
and shared blocks are kept. A storage bar shows usage against the global backup
limit and updates after deletion.
Clean up all unprotected backups in one confirmed operation. A loading bar
shows the initial load, requested refreshes and cleanup. Later automatic polls
keep the interface steady and deletion controls available; manual operations
take priority safely over the background backup queue.
When a new backup needs more room, GitThul removes only the additional versions
needed, preserving every repository's latest valid copy. Lowering the storage
limit previews the impact and requires confirmation when versions must be
removed. Limits below the space needed for protected copies are rejected.

Automated checks cover the new behavior, including real Git repositories; visual checks
use simulated browser data. Native UI and package installation have not been
manually verified for this version. Windows installers have no commercial
signing certificate; macOS applications use ad hoc signing without notarization.
