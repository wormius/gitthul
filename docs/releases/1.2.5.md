# GitThul 1.2.5

GitThul™ 1.2.5 alinea mejor el diff normal cuando una edición mezcla cambios de
contenido con una conversión entre finales de línea LF y CRLF. Las inserciones y
eliminaciones ya no desplazan las parejas de las líneas siguientes en la vista
dividida, para que puedas revisar y preparar el cambio que elegiste.

Las líneas cuyo único cambio es el terminador se distinguen con una marca
discreta y las etiquetas LF/CRLF junto a su número. Siguen siendo cambios reales:
seleccionar esas líneas o preparar su bloque incluye también sus terminadores.

## Mejoras y correcciones

- Stage, Unstage y Descartar usan el mismo alineado que el visor. Las operaciones
  parciales conservan los bytes de las líneas elegidas y las modificaciones que
  no seleccionaste, también al combinar inserciones, líneas repetidas y cambios
  de terminador.
- Al preparar o retirar solo un lado de un reemplazo, se conserva el orden de
  las líneas. Se corrige el caso que podía invertir el contenido anterior y el
  nuevo durante una operación parcial.
- Si una selección dejaría una línea sin terminador antes de otra línea, la
  operación se rechaza antes de escribir y pide seleccionar ambos lados o el
  bloque completo. No se añade un salto ni se unen líneas de forma implícita.

## Compatibilidad y validación

Pasaron las comprobaciones locales de tipos, lint y formato, las compilaciones
web y nativa en Linux, 3.169 pruebas de frontend y 594 pruebas nativas; otras
6 pruebas nativas quedaron omitidas. Las pruebas nativas de operaciones parciales
comprueban el contenido real del índice y del árbol de trabajo en repositorios
temporales. La vista dividida y una selección de línea también se revisaron en
navegador con datos de prueba.

No se ha realizado una comprobación manual de este parche ni de sus instaladores
en Windows o macOS. Windows sigue sin certificado comercial; macOS utiliza firma
ad hoc, sin notarización. Consulta los pasos y avisos de la guía de instalación.

## English summary

GitThul™ 1.2.5 aligns normal diffs when content edits are mixed with LF/CRLF
conversion. Insertions and deletions no longer shift subsequent line pairs in
the split view. Lines that only change their ending have LF/CRLF labels and
remain selectable changes, including when staging a whole block.

Stage, Unstage and Discard share the viewer's alignment and preserve selected
bytes and unselected changes. Partial operations preserve line order. A selection
that would leave an unterminated line before another line is rejected before
writing; select both sides or the whole block instead.

Local Linux checks, web and native builds, 3,169 frontend tests and 594 native
tests passed; 6 native tests were skipped. The split view and a line selection
were also checked in a browser with test data. Manual verification of this patch
and its installers on Windows or macOS has not been performed. Windows installers
have no commercial signing certificate; macOS uses ad hoc signing without
notarization.
