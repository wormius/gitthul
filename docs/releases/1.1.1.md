# GitThul 1.1.1

GitThul™ 1.1.1 corrige la apertura de repositorios que conservan una rama upstream
configurada cuya referencia remota ya no existe. También mejora la precisión de
los conteos de commits y el diagnóstico de errores al cargar referencias.

Conserva las funciones de [1.1.0](1.1.0.md). El código propio se distribuye bajo MIT.

## Apertura y referencias

- Un upstream eliminado, por ejemplo después de `fetch --prune`, permite abrir
  el repositorio y consultar sus ramas, historial y archivos. GitThul indica
  que ese upstream no está disponible y conserva la configuración del repositorio.
- Las ramas con upstream ausente no muestran conteos de commits por delante
  o por detrás ni se consideran sincronizadas con el remoto.
- Los conteos usan las revisiones exactas de las ramas. Un tag o una rama local
  con el mismo nombre corto que el upstream ya no cambia el resultado.
- Los objetos dañados y los fallos reales de Git siguen mostrando un error.
- Si crear una rama y cambiar a ella sobrescribiría archivos locales, la
  notificación explica el bloqueo y recomienda crear un stash o hacer commit.
  Los cambios compatibles con el destino siguen permitiendo crear la rama.

## Diagnóstico

Los errores de lectura, escritura e integración con Git conservan el paso que
falló, sus causas disponibles y evidencia estructurada. Los comandos incluyen
argumentos protegidos, código de salida y `stderr`; los errores de disco conservan
su tipo y código del sistema. Cada fallo relaciona el diagnóstico nativo con la
operación y hasta 12 pasos anteriores, también sin activar debug.

Los reportes JSONL comienzan con un resumen del entorno y de las incidencias
repetidas. La protección de secretos es recursiva y se aplica antes de guardar
y al exportar entradas antiguas. Los recortes y pérdidas conocidas de evidencia
se indican en el reporte. Las lecturas rutinarias generan menos entradas de debug.

Consulta la [guía de registros](../logs-diagnostico.md) para exportar un reporte.
Revisa el archivo antes de compartirlo: puede contener rutas locales y nombres
de referencias.

## Validación e instalación

La corrección incluye pruebas con repositorios Git temporales para upstreams
eliminados, nombres homónimos, repositorios bare, worktrees y objetos ausentes.
La comprobación manual con el repositorio del reporte y la validación nativa en
Windows y macOS siguen pendientes.

Consulta la [guía de instalación y dependencias](../instalacion.md) para instalar
el paquete correspondiente a tu sistema cuando se publique esta versión.
